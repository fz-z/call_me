# 实时模型音色试听设计

## 目标与边界

在声音库的音色详情页，为每条已复刻的实时模型绑定提供独立的“试听”入口。管理员输入本次试听文案，系统使用该绑定所属的真实实时模型及其克隆音色生成一段短语音并播放。文案只在本次页面操作中使用，不写入音色档案或数据库，也不影响现有经典 TTS 试听。

该功能是音色预览，不创建 Agent、LiveKit 房间或通话记录，不修改模型配置及音色绑定，也不删除供应商侧资源。模型是实时对话模型，后台会要求它仅朗读文案，但生成内容可能略有改写；界面须说明试听主要用于判断音色，不承诺逐字一致。

## 交互

- 每个“实时模型音色”绑定卡片显示“试听”和“重新复刻”。未绑定的音色没有实时试听入口；经典 TTS 区域继续保留自己的试听按钮。
- 点击实时“试听”打开弹窗，显示目标模型名称、可编辑的文案输入框、示例文案、生成按钮和音频播放器。初始文案为“你好，这是实时音色试听。”，只存在于弹窗状态，不存储。切换绑定时重新初始化文案。
- 文案去除首尾空白后不能为空，最多 120 个 Unicode 字符；超限在前端立即提示，后端重复校验。提交后按钮显示生成状态并禁止重复提交。每次点击均新建一次有计费可能的供应商会话，界面给出简短说明。
- 成功后展示本次 WAV 音频的播放/暂停控件；再次生成时先停止并释放旧音频。关闭弹窗、切换音色详情或离开页面时取消前端请求并释放播放器与 Blob URL；旧响应不得在新绑定下播放。
- 错误留在弹窗内：校验错误、绑定不存在、供应商拒绝、超时、返回空音频或播放失败均给出明确提示。失败后保留本次输入，允许重试。

## 后端数据流

- 新增管理员专用 `POST /api/admin/voices/{voice_id}/realtime-bindings/{realtime_config_id}/audition`，请求体只有 `text`。响应复用短音频数据模式：`audio_base64` 与 `mime_type=audio/wav`。不得返回供应商音色 ID 或 API Key。
- 请求先按音色 ID 与实时配置 ID 联合查询 `voice_runtime_bindings`，只接受 `runtime_kind='realtime'` 的绑定；同时读取对应的 Qwen 配置与其关联密钥。不存在返回 404，配置或密钥无效返回清晰的 400/502，不回退到经典 TTS 音色。
- 独立的实时试听服务建立一次短暂 WebSocket 会话，在首次 `session.update` 中设置目标模型绑定的供应商音色、音频输出模态和 24 kHz PCM 输出。随后注入一条文本消息，要求模型仅朗读管理员文案，再发送 `response.create`。
- 收集 `response.audio.delta` 的 PCM16 片段，直到 `response.done`。只接受 `completed` 且有音频的结果；检查片段编码和样本对齐。把收集的单声道 24 kHz PCM 封装为 WAV 后返回。所有路径均关闭 WebSocket 与 HTTP session。
- 总生成时限 35 秒，PCM 总量不超过 2 MiB；超时和过量直接终止会话并返回明确错误，防止小内存服务器无限等待或堆积音频。供应商错误对管理员说明类别，但日志和响应都不得包含密钥、WebSocket 授权头或音色 ID。

## 结构与测试

- `api/realtime_audition.py` 仅负责供应商会话、事件解析、PCM 上限及 WAV 封装；`api/voices.py` 负责权限、文本与绑定校验、配置解析及 HTTP 错误映射；`api/models.py` 定义请求体。
- `web-admin/src/components/RealtimeVoiceAudition.vue` 管理弹窗、文本输入、请求代次、播放器和资源释放；`VoiceDetailView.vue` 只决定哪个绑定正在试听并传入名称和 ID。
- 后端用可注入的假 WebSocket 测试事件顺序、正确选用绑定音色、成功 WAV、空音频、错误、超时、过量和资源关闭；接口测试覆盖权限、文本边界、绑定不存在及无数据库写入。前端测试覆盖文案校验与过期响应隔离，构建检查组件集成；人工检查桌面和窄屏弹窗及实际播放。
- 不在自动化测试中调用付费供应商。上线后的真实试听需由管理员在已有实时绑定上手动验证，不自动触发付费试听。
