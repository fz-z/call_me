# 声音库详情页与绑定管理交互设计

## 目标

把当前“管理音色绑定”大弹窗改为独立详情页，让管理员先看清已有音色能用于哪些模型，再按需执行编辑、试听或复刻。修正 TTS 运行时绑定被误显示在“端到端实时绑定”中的问题。已复刻的实时音色应明确标注可在同一实时模型配置的多个 Agent 和后续通话中重复使用。

## 范围

- 声音库列表保留创建经典音色、创建端到端音色的入口；每个音色的“管理绑定”改为“查看详情”，进入 `/voices/:id`。
- 详情页包含概览、端到端实时、经典 TTS、基本信息四个区域。每个区域只展示本类数据及本类操作。
- 延续现有试听能力：经典 TTS 可直接试听；端到端实时音色说明需通过使用该音色的 Agent 发起实时通话试听，不伪装成 TTS 试听。
- 不改变现有数据库、供应商音色 ID 的保密边界、Agent 选择规则或声音克隆接口。声音列表和更新响应需返回非敏感的 `audition_text`，以便刷新后显示已保存的默认试听文本。

## 信息架构与操作

1. 列表显示名称、类型、经典 TTS 绑定、端到端实时绑定、使用中的 Agent。端到端列只使用 `runtime_kind === 'realtime'` 的记录；TTS 列继续使用 `/tts-configs` 的关联信息。
2. 点击音色名称或“查看详情”进入详情页，顶部显示返回声音库、名称、类型和使用中的 Agent 数量。
3. 端到端区域先显示已复刻的实时模型配置卡片，包括配置名称和模型。卡片说明“已复刻，可供此配置下的多个 Agent 和后续通话重复使用”，不要求再次上传。空状态说明尚无实时绑定。
4. “复刻到其他实时模型”打开独立表单，按顺序选择支持 `voice_clone` 的实时配置、上传参考音频、确认授权，再提交。已绑定的配置不出现在新增选项中。无可选配置时指向“实时模型”管理页。
5. 已绑定卡片的“重新复刻”是次级操作，打开同一上传表单但固定目标配置。提交前再次确认：新音色会替换此配置当前绑定，使用这组绑定的 Agent 后续通话将使用新音色。取消不发请求。
6. 经典 TTS 区域展示已有 TTS 关联，可添加或移除关联，并提供经典试听入口。TTS 区域不显示实时上传控件，端到端区域不显示 TTS 试听文本。
7. 基本信息区域单独编辑音色名称和经典 TTS 默认试听文本；保存只调用现有 `PATCH /admin/voices/{id}`。

## 数据流与边界

- 详情页通过现有 `/admin/voices` 找到当前档案，再读取 `/admin/voices/{id}/tts-configs`、`/admin/voices/{id}/runtime-bindings`、`/admin/agents` 和配置池数据。若音色不存在，显示明确提示和返回入口。
- 前端集中筛选实时绑定；`runtime_kind='tts'` 不得进入任何端到端展示或“已复刻”判断。后端接口仍可返回两类记录，以兼容其他使用方。
- 新增和重新复刻均调用现有 `POST /admin/voices/{id}/realtime-bindings`。成功后重新读取绑定，不在前端保存或展示供应商音色 ID。
- 同一实时配置已存在绑定时，详情页只提供复用和有确认的重新复刻，不提供重复的“新增”入口。不同配置仍需分别建立绑定；不自动复制供应商音色 ID。
- TTS 关联仍调用现有添加/移除接口；已被 Agent 使用时若后端拒绝，展示服务端错误，不在前端静默移除。

## 错误与反馈

- 音频格式、大小和时长沿用现有前端校验及后端限制；错误显示在对应操作表单内，避免被页面其他区域淹没。
- 提交期间禁用重复提交，成功后关闭表单并更新当前区域；失败保留已填写的信息以便重试。
- 首次加载失败显示页面级错误和重试；单个绑定请求失败显示对应区域错误，不把请求失败误呈现为“未绑定”。
- 不新增自动部署、批量迁移或供应商侧音色删除行为。

## 验收

- 截图中的 TTS Flash 只出现在经典 TTS 区域，不出现在端到端绑定区域。
- 已复刻实时模型显示“可重复使用”；管理员无需再次上传即可在同配置的 Agent 创建/编辑页选择该音色。
- 新增实时绑定仅列出未绑定且支持音色复刻的配置；重新复刻固定目标并在覆盖前确认。
- 名称、TTS 关联、实时复刻和经典试听分别可操作，错误提示停留在对应操作附近。
- 浏览器刷新详情页可恢复到同一音色；无效音色 ID 有可理解的空/错状态。
- 管理端构建及相关自动化测试通过；必要时人工检查桌面窄宽度下卡片和表单不溢出。
